# 2026-11-26

## 功能区头像：本地副本 + 启动一次更新校验（0.2.6）

用户原话：「对于功能区展示的用户头像，我希望能保存在本地，这样就算离线也能显示，
每次加载插件时只对头像作更新较对，没有新的头像则沿用旧的」。

### 做了什么

1. **`src/features/avatar/avatarCache.ts`（新）**：每个平台一份 JSON，落在
   `{configDir}/plugins/ob-sync/avatar-cache/{host}.json`。内容是 base64 图片 +
   远端地址 + 令牌指纹（令牌明文不落盘）。用 `DataAdapter.read/write`，
   与 0.2.6 之前那条「只存内存」的路相比，离线时才有图。
   - 用文本 JSON 而不是 `readBinary/writeBinary`：移动端实现不一致；
     手写 base64（不用 `Buffer` / `btoa`）也是为两端都能跑。
   - 每个平台只留最新一份，令牌换了指纹就不匹配 —— 不会把上一张脸画到新账号上。
2. **`ribbonAvatar.ts` 改成两段式**：先 `store.read` 立刻画旧图 → 再对每个
   「平台+令牌」身份做**一次** `lookup`。接口地址与缓存相同 → 沿用旧图
   （不下载、不写盘）；不同 → 下载新图、落盘、重画。校验 / 下载 / 写盘失败
   一律保留旧图。`checked` 让 layout-change 不再反复请求；换平台 / 换令牌 /
   重载插件才算新校验。另加 `destroyed` 标志：卸载后回来那张图不会再挂上节点。
3. **`main.ts`**：注入 `createAvatarStore(app, manifest.id)` 与基于 `httpRequest`
   的下载（retries 0、10s 超时、MIME 兜底 image/png）。头像只是装饰，
   拉不到就留旧图，不该拖住启动。
4. 中英文案补上「本地保存 / 离线可见 / 启动时检查一次」。
5. 测试：新增 8 条覆盖缓存优先、离线沿用、地址不变不下载、新图落盘、
   下载失败降级、令牌指纹隔离、写盘失败照常显示、卸载后不复活；
   `pluginBoot.test.ts` 的微任务等待改成多轮（异步链变长了）。
