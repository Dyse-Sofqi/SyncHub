### 审核复查（用户点名的那条）

`eslint-plugin-obsidianmd` 全量跑下来：**obsidianmd 的 error 级规则零违规**，
只剩一条已知的 `settings-tab/prefer-setting-definitions`（warning，有意保留）。
`no-static-styles-assignment` **0 违规**。

但手工 grep 抓到**一处踩形式边界的写法**：`settingsTab.ts` 里
`const FULL_WIDTH = "100%"; areaEl.style.width = FULL_WIDTH;` —— 规则**只拦字面量**，
用 `const` 就绕过了。代码注释自己写着「说实话这就是在踩规则的形式边界」。
已收回 CSS 类（`.obsync-gitignore` 加 `width:100%` / `box-sizing:border-box`），
元素上不再写内联；`settingsTabRender.test.ts` 那条用例**翻面**（从「必须内联」
改成「不许内联」）。

剩下三处 `.style.*`（`ImagePreviewModal` / `ImageEditorModal`）是**动态值**
（模板字符串），规则显式放行，属设计意图，**没动**。

> **规则细节（别再记错）**：`no-static-styles-assignment` 只认
> ① `el.style.x = 字面量`、② `el.style.setProperty("x", 字面量)`、
> ③ `el.setAttribute("style", 字面量)`、④ `setCssProps/setCssStyles` 里**带引号且不以 `--` 开头**的键。
> 变量赋值与模板字符串**不报**。`setCssProps({ width: "100%" })` 用**不带引号的键**时不报，
> 带引号才报 —— 之前 HANDOVER 写的「`setCssProps` 同样违规」不够准确，已改。

### 发版：GitHub 走 REST API，Gitee 走镜像

- **GitHub**：用 Git Data API 重建本地提交（blob → tree(base_tree) → commit → PATCH ref），
  **SHA 与本地逐字节相同**（`f1bc8b4`）。两个安全闸门都过了：
  `tree aa5e5cad` 一致、`commit f1bc8b4` 一致。tag `0.2.0` 同样用 `POST /git/refs` 建。
  最后 `gh api --input _release_payload.json` 建 release + `gh release upload` 传三件套，
  资产 sha256 与本地**逐项相同**。
- **行尾**：`core.autocrlf=true`，51 个变更文件里 **16 个是 `i/lf w/crlf`** ——
  上传前必须归一为 LF（否则 tree MISMATCH）。判据取自 `git ls-files --eol`（**制表符分隔**）。
- **Gitee**：镜像**自己就把提交和 tag 同步过去了**（`branches/main` = `f1bc8b4`、
  tag `0.2.0` 已在），所以**一行 git push 都不用**，直接跑
  `GITEE_TOKEN=… node scripts/gitee-release.mjs 0.2.0` 即可（脚本幂等、附件逐个传、末尾核对数量）。
  下载回来 sha256 与本地逐项相同。
- 仓库**没有 `.github/workflows/`**，所以不存在「tag 触发的工作流抢建 release」那类坑
  （`actions/runs` 的 `total_count` 恒 0，符合预期）。
